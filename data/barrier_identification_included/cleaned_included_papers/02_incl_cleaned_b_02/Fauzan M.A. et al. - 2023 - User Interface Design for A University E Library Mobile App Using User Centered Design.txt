The e-library mobile application's design was performed 
using the UCD method. This method has four steps to follow: 
a) context analysis; b) defining the requirements; c) design; d)
evaluation. It will require a systematic for each step to achieve
the goal. Fig. 1 is a diagram of the stages of the research
carried out.

C. Design 
This stage was done to understand better how the final 
product will look and operate. All the work in this stage was 
carried out using Figma. The outputs of this stage are low-
fidelity design, high-fidelity design, and prototype. 

1) Low-Fidelity Design: Before making the final product, 
researchers created a low-fidelity design that forms 
wireframes from the e-library mobile application design 
based on needs. The goal of making low-fidelity designs is to 
get feedback from the user at the initial stage. Fig. 4, Fig. 5, 
and Fig. 6 show examples of low-fidelity designs created in 
this research.

The onboarding screen appears when the user opens the 
application without logging into an account. The registered 
username and password must be entered to log in. If the user 
has no account, they must first register by clicking the register 
button. They will then be prompted to input the necessary data 
to set up an account. Fig. 7 shows the high-fidelity design for 
the onboarding page. 

Once the user has logged in with an account, the home 
page is shown. On this page, users can access search catalogs, 
the latest catalogs, and other information, which contains 
news, important information, e-journals, e-books, magazines, 
and infographics. And the service contains submissions for 
literacy class schedules, literacy class attendance, guidance 
requests, and room reservations. Fig. 7 shows the high-
fidelity design for the home page. 

The Catalog page is the main page for searching catalogs. 
It allows users to see a list of all available catalogs or perform 
searches using regular or detailed searches. Fig. 8 shows the 
high-fidelity design for the catalog list. 

To find detailed information about the catalog, abstracts, 
PDF files, and reviews are all accessible via the catalog detail 
page. Users can visit this page after choosing the catalog they 
wish to browse. The high-fidelity design for the catalog detail 
page is displayed in Fig. 8. 

On the live chat page, users can immediately interact with 
an e-library administrator, who will then assist in responding 
to their questions. Fig. 9 shows the high-fidelity design for the 
live chat page. 

On the profile page, users may log out of their accounts 
and examine details about the library and services offered 
outside of the e-library. Fig. 9 shows the high-fidelity design 
for the profile page.

III. ANALYZE RESULTS 

A. Testing and Evaluation Scenarios 
The evaluation process in this research was carried out 
online using a Zoom meeting. The participants who 
participated in the evaluation were the same as in the previous 
interview and usability testing. The test scenario begins by 

asking the participants to complete the 7 tasks in Table I. After 
completing the task, participants will be asked to fill out the 
SEQ questionnaire, which contains 7 questions, and the SUS 
questionnaire contains 10 questions. The data was used to 
determine the task's ease and the design's usability score. 

B. Questionnaire 
1) SEQ Questionnaire: The SEQ questionnaire was 
administered to participants after they completed the task. 
The question in Fig. 12 was answered on a seven-point scale 
[9]. The function of using SEQ is to get a comparison on the 
part of the user interface that is problematic according to the 
participant because the participant still remembers the 
experience felt when performing the task so that the 
participants can provide a clear assessment of their view of 
the experience. 

 
Fig. 12. Single Ease Question 

2) System 
Usability 
Scale 
Questionnaire: 
SUS 
questionnaire contains 10 basic and straightforward questions 
about the usability of a system. Participants answer SUS 
questions on a scale between 5 points (Strongly agree) and 1 
point (Strongly disagree) [10], which consists of 5 positive 
and negative questions. The scale is calculated, and the result 
is a value of 0-100 the greater the value, the better the 
usability of the product Tested. SUS is also proven to get 
valid results even using a small sample [11]. The following 
are the questions asked: 

1. I think I will use this system again. 
2. I find this system complicated to use. 
3. I found the system easy to use. 
4. I need help from other people or technicians in using 
this system. 
5. I feel that the features of this system are working 
properly. 
6. I feel that there are many things that are inconsistent 
(incongruent in this system). 
7. I feel that others will understand how to use this 
system quickly. 
8. I find the system confusing. 
9. I feel there are no obstacles in using this system. 
10. I need to familiarize myself before using this system.

IV. CONCLUSION AND FUTURE WORK 

This research's main goal was to design an e-library 
mobile application that matches user needs with a good 
usability score. The design was conducted with the UCD 
method, which was chosen because collaboration between the 
user and the designer is needed to match the user interface 
with the user’s needs. This method has 4 phases: context 
analysis, defining the requirements, design, and evaluation. 
After completing all phases, it has been shown that using the 
UCD method can get good results, which can be seen when 
the design is evaluated. The evaluation is conducted with SEQ 
and SUS questionnaires. The results obtained from SEQ are 5, 
6, 7. And 88,5 for SUS, which is in grade B based on the grade 
scale in Fig. 7. These results indicate that the solution of the 
design made using the UCD method is acceptable. 

In the future, it is necessary to design a full-site mobile 
version of Telkom University's e-library. Because this 
research only designs on public pages that most users usually 
access. By designing the full-site mobile version of the e-
library, it can get the design for all interactions in the e-library 
application. Therefore, the final application can be developed.
